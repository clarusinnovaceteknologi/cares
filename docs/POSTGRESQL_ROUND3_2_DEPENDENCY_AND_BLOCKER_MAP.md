## 1. Classification scheme (required)

Each dependency is classified as one of:
- **Owner decision resolved:** owner decision fully resolved for the relevant scope (no material unresolved technical/policy detail remains for that dependency). *Not claimed in this consolidation except where explicitly evidenced; none claimed here.*
- **Principle approved, technical details deferred:** owner-approved principles/bounded conditions exist (Round 3.2), but technical details, validations, or formal approvals remain unresolved.
- **Partially resolved:** some elements resolved by explicit evidence/approval, others unresolved (must be specific).
- **Still blocked:** dependency cannot be satisfied/proceeded for affected scope due to missing approval/decision/evidence/prerequisite.
- **Requires technical validation:** resolution/feasibility/readiness depends on technical design review, testing, measurement, or security/operability validation evidence.
- **Requires separate owner authorization:** progression/execution requires an explicit owner authorization record (distinct from principle approval/decision consolidation).

**Rule:** a technical blocker is **not** marked resolved merely because its governing principle was approved.
